Problema
O erro "Field name missing" acontece porque o Postman está enviando o arquivo sem o nome de campo correto no form-data. O FileInterceptor('file') espera um campo chamado file no body da requisição.

Como configurar no Postman
Mude o método para POST
Vá em Body → form-data
Na coluna Key, digite exatamente file e mude o tipo para File
Na coluna Value, selecione o arquivo
Show Image

⚠️ O nome do campo na Key deve ser idêntico ao que está no FileInterceptor('file').

Verificações no código
Seu código está correto, mas adicione uma validação para evitar crash se nenhum arquivo for enviado:

typescript
// controller
@Post('upload')
@UseInterceptors(FileInterceptor('file'))
async upload(@UploadedFile() file: Express.Multer.File) {
    if (!file) {
        throw new BadRequestException('Nenhum arquivo enviado');
    }
    return await this.animalService.upload(file);
}
Garantir que o Multer usa memória (buffer)
Por padrão o NestJS já usa memoryStorage, mas para deixar explícito e evitar problemas:

typescript
import { FileInterceptor } from '@nestjs/platform-express';
import { memoryStorage } from 'multer';

@Post('upload')
@UseInterceptors(FileInterceptor('file', {
    storage: memoryStorage(), // garante que file.buffer estará disponível
}))
async upload(@UploadedFile() file: Express.Multer.File) {
    if (!file) {
        throw new BadRequestException('Nenhum arquivo enviado');
    }
    return await this.animalService.upload(file);
}
Sem memoryStorage(), o Multer pode salvar em disco e o file.buffer fica undefined, quebrando o fs.writeFile.

Checklist rápido
O que verificar	Esperado
Key no form-data do Postman	file (exato)
Tipo do campo no Postman	File (não Text)
Header Content-Type	Não definir manualmente — o Postman gera o multipart/form-data com boundary automaticamente
O erro mais comum é justamente setar Content-Type: multipart/form-data manualmente no Postman sem o boundary, o que corrompe a requisição. Deixe o Postman gerar automaticamente.
